# Aiplot

Sole spec for this repo. If code and this file disagree, ask the user. Section refs: §n.

## 1 Overview
Local Windows desktop app (NVIDIA 8GB VRAM) for writing Korean web novels. All models/data local. AI proposes, user decides.
- Stage 1 Planning: user chats with LLM → LLM tidies chat into source notes → cards generated from notes → user saves. Cards: world, character, region, main_story, part, episode.
- Stage 2 Direction: per episode, AI splits into scenes, recommends 1–3 technique cards/scene (1 → auto-picked, 2–3 → user picks), builds plan (chapter → scene → beat). User confirms per episode.
- Stage 3 Writing: LLM writes beat by beat (500–1000 chars, 6–10 beats/chapter, ~5500 chars/chapter incl. spaces), tracks state, checks consistency.
- Starting a stage locks earlier stages (read-only).

## 5 Conventions
- English code/comments/commits; Korean user-facing text in `app/src/strings/`.
- Conventional Commits; scopes app|server|schemas|training|ci|docs. Small changes (one screen/endpoint group/service).
- Names: React PascalCase files; TS camelCase; Python snake_case; DB snake_case singular tables; API plural nouns, camelCase path params; JSON fields snake_case except job/SSE payload keys in §16; error codes UPPER_SNAKE; ID prefixes: w_ work, c_ card, tech_ technique, pl_ plan, ch_ chapter, b_ beat, wr_ warning, job_ job, ms_ milestone, fs_ foreshadowing, wl_ worldline, cv_ cover, dr_ draft.
- TS: strict, no `any`; server types only from generated; server data only in TanStack Query.
- Python: full type hints, mypy clean, Pydantic I/O; routers thin → services → db (SQL only in db/); multi-table writes in one transaction; work >10s runs as a job with SSE; LLM calls only via router by role.
- Format changes: edit `schemas/` → codegen → commit generated. Card field change → bump `schema_version` + migration + backup import conversion.
- Prompts: files only; never edit old version, add v{n+1}, update roles.yaml; store prompt version with every output; context blocks tagged `<원문> <참고 카드> <상태> <지시> <대화>`; JSON roles pass schema as llama.cpp `json_schema`.
- DB changes only via migrations.
- UI: one accent color per screen; irreversible = red, never default, strong ones require typing work title; warnings orange; never color-only meaning; motion only on state change 0.2–0.3s, the S1 page turn 0.75s (respect reduced motion); waits >10s show progress, ETA, background option; themes light/dark/system (light default); manuscript 17px, line-height 1.7. Look: calm wooden study with paper books — tokens in `app/src/styles/base.css` (paper, sepia ink, oak/walnut, brass accent; wood grain = `app/scripts/wood/*.svg` rendered to WebP 1x/2x in `app/src/assets/wood/` by `npm run wood`, alpha-only noise stretched along the board and banded into growth rings over the theme's wood colour, one grain per plank, joints breaking the grain (bookcase back: 200px planks, faint joints); cover lettering ≥4.5:1 on every book colour); font 본고딕 Source Han Sans KR 2.005R Regular/Medium/Bold (bundled OTF + OFL in `app/src/assets/fonts/`); mouse cursor = quill, nib bottom left (`app/src/assets/cursor/`, gilt over clickables; text fields keep the I-beam; wherever the image would cross a window edge (top/right: within its size; left/bottom: the outermost 2px), where Chromium swaps custom cursors for the default, `src/cursor.ts` hides the cursor and draws the quill itself).

## 6 Prohibitions
- Never edit card fields directly; change source notes and regenerate. Exceptions: region `map_x/map_y`; timeline node drag (LLM writes one line into notes, user confirms).
- Never persist conversations (memory only, discard on drawer close) or unsaved drafts.
- Never modify locked-stage data: server returns 423 STAGE_LOCKED. Never reopen a stage without snapshot.
- Never hand-edit generated files. Never query references from card `data`; use relation tables.
- Never trust LLM char counts; count in code incl. spaces.
- No runtime network use of user data, no telemetry; external LLM APIs only in training/.
- No embeddings/vector search/sqlite-vec. No model files in repo/installer. No torch/transformers in server. No Ollama. No macOS/Linux code. No automatic user backups. No app data outside data dir (except user-chosen export/backup paths). No real models in unit tests. No training/eval data in training/generate. No other authors' novels as training data. No work beyond current dev step (§20) unless asked.

## 7 Domain
- world: one setting topic per card (magic system, faction, era, terms…); category rule|faction|history|culture|other; summary; details; rules[{rule,exception}] (world-rule check evidence); terms[{term,meaning}]; related (character/region/world cards).
- character: theme; personality{traits, behaviors[{situation,action}]} (check evidence); speech{description, examples 3–5} (writing quality); appearance (initial); relations; origin_region.
- region: parent; links[{target, travel{value,unit,mode}, direction?}] (travel = evidence for impossible-movement check); appearance; environment{natural,social}; sensory{smell,sound,mood}.
- main_story: theme, premise, ending, milestones. Creation order main → parts → episodes.
- part: order, title, theme, fulfills[milestone], start, end, structure?. All milestones must be assigned to exactly one part before episodes. Deleting/merging part with episodes: ask move or delete.
- episode: part, order (within part), theme, relation_to_main, fulfills, characters, locations{main,others}, world (world cards used; stage 2–3 context), links{prev,next,causes}, foreshadowing{plants,payoffs}, worldline, structure{type 4|5, stages[{name,summary,tension 1–5}]}, synopsis, summary (stage 3).
- Structure: 5-stage 발단·전개·위기·절정·결말 (conflict bursts); 4-stage 기승전결 (situation flips). AI recommends with reason, user picks. Map 기=발단, 승=전개+위기, 전=절정, 결=결말; 5→4 auto, 4→5 AI proposes split of 승, user confirms.
- Worldline: branch_episode_id; pre-branch episodes in all worldlines; hide tabs if one.
- Completeness: milestone fulfillment, unresolved foreshadowing, incomplete cards (missing required fields, incl. empty structure stages).
- State keys (fixed): location{region_id}; injury{part,severity,since_chapter,healed?}; item{name,action gain|lose}; knows_secret{secret,since_chapter}; relation_change{target_id,change}; appearance_change{text}. Appended per beat; context uses latest per card+key.

## 8 Stage 1 UI
Card drawer (all types): ~70% width, background dimmed; left chat (top) + source notes (bottom), right card preview; X/Esc closes. Opened by world book "+ 새 설정", dex "+", card "원문 수정", "+ 새 에피소드", "+ 새 지역", main/part setup (story screen).
- Header: type, new/edit, name; world shows category; episode shows part+region; part shows milestones.
- `chat` replies and asks for missing info; new cards may open with question/draft; parts open with LLM draft. After each reply `source` edits notes sentence by sentence (reversals resolved; untouched sentences and layout stay byte-identical; changed sentences briefly highlighted). User may edit notes.
- Model context: last few turns + notes + `@` cards.
- "카드 생성" → draft → "저장" writes notes+card+relations in one transaction. Unsaved close asks to save.
- Edit mode: load notes, new chat; regeneration shows only changed fields with old values struck; list cards referencing changed name/relations/characters before save.
- Pinned fields survive regeneration. `@이름` autocomplete. Generation inputs: notes + `@` cards + world cards (name/category/summary each; over ~800 tokens → names + category only, `@` world cards and, in edit mode, the card's saved related world cards in full; measure in unit 15) + prior-stage cards (episode: main, part, regions).
- Click field → highlight evidence sentences; no evidence → "AI 추정". Empty required → "아직 정해지지 않음" + follow-up question (world category is inferred by `card`, always filled, never in chat's missing items or asked). Similar names (레오/래오) → ask same entity.
- Type section: world rules (with exceptions) + terms; character speech preview; episode 4/5 picker with recommendation; part milestone assignment.
- After save: close, highlight card 0.3s. Locked: add/edit disabled, drawer won't open.

World book (S1-0): open encyclopedia. Left page: category bookmark tabs (규칙·능력, 세력·조직, 역사·사건, 문화·용어, 기타) + entry index with dotted leader and page number; "+ 새 설정" (current tab's category goes to `card` as a hint; the saved card lands where its generated category puts it); 용어집 last (all terms 가나다 order → their entry). ## 9 Stage 2
Flow: select episode → `pick` (input: episode + technique list titles/one-liners) → scenes + 1–3 picks with rank, reason → auto-pick if 1, else user (keys 1–3, Enter = top) → `direct` (chosen cards' definition/effect/caution) → plan → user edits → confirm. All confirmed → "집필 시작" (lock warning).
Plan decides narration order (flashback, in medias res, reveal timing), chapter split (1–5/episode, cut on hooks), per beat pov, mode 장면화|요약 (narration), focus 감정|행동|정보 (what the beat dwells on), density 담백|자세히 (how much detail, independent of focus; AI proposes, user changes), tension, target_chars.
```json
{"episode":"episode_007","chapters":[{"chapter":1,"target_chars":5500,"cut_after":"episode_007.위기",
"scenes":[{"scene":1,"source":"episode_007.위기",
"picks":[{"technique":"tech_04","name":"인 메디아스 레스","rank":1,"reason":"..."},{"technique":"tech_09","name":"시간 순 전개","rank":2,"reason":"..."}],
"chosen":"tech_04","reveal":["..."],
"beats":[{"order":1,"pov":"테오 1인칭","mode":"장면화","focus":"감정","density":"자세히","tension":4,"target_chars":800}]}]}]}
```
`source` = episode.stage; beat order = narration order; `reveal` optional.
Technique card: id, name, definition, effect, caution, source; ≥30 in `server/data/techniques/`, shared across works.
S2 screen: left episodes; center dual timeline (top story order, bottom narration, same event linked, reordered in accent) + tension curve with dashed chapter cuts; right technique picker + evidence. Top pick: glowing border + "✦ 추천" + reason (thick border if reduced motion). Changing a scene's card re-plans its beats. Beat drag → recheck changed part only. Cut drag → update chars/chapter. Beat select → technique, card, reason; "좋음/별로"+note stored as training feedback. "기획 보기" opens stage 1 read-only.

## 10 Stage 3
Beat loop: build context → `write` (stream by sentence) → count chars → `check` (state + warnings) → `summary` (progress) → adjust next target from remaining.
Write context (~6000/8k tokens, measure in step 1): instructions + style framework ~1000 (style v1 every-beat part measured 633 tokens, examples +105, Qwen3 tokenizer; v2 is the style to use, every-beat 905 chars + matched by_mode/by_focus ~150–220 chars; role, summary, rules, dialogue, format and plain banned phrases every beat; examples and by_mode/by_focus/by_density/by_pov/by_tension matching the beat (v2 has no by_density yet and its by_focus mixes in density; style v3 in step 7 splits it out) (by_pov heading = substring of beat pov, e.g. 1인칭); empty sections omitted; its format rules override the basic format below; banned phrase or /regex/ (no multiline: ^ = beat start; regex only checked, never shown) in a beat → regenerate that beat up to 3×, then keep last + warning; style id+version stored with output); beat instruction ~300; summaries ≤2000 chars ~1500; previous ~1000 chars ~800; appearing characters + speech examples ~1000; world cards of the episode + those related to appearing characters/regions (summary, rules, terms) ~400; latest state ~200; output ~800. Order: instructions + every-beat style sections first, byte-identical across beats (no per-call values) so llama.cpp prompt cache reuses them → beat-matched style sections → rest.
Summaries: chapter.progress_summary 300–500 (after each beat; covers current chapter before last 1000 chars); summary_long ~1000 (chapter end; previous chapter only); summary_short ~200 (chapter end; earlier chapters of episode); episode.summary ~300 (episode end; recent episodes). Cap 2000 chars, drop oldest episode summaries first. Edit or regenerate → redo chapter summaries + state.
Checks: out-of-character actions, appearance mismatch, impossible travel, state contradictions, world-rule violations (world card rules). Warning: kind, sentence position, evidence card, reason. Group same type; ignore reasons feed later checks; sensitivity setting.
Format: short paragraphs, frequent breaks, dialogue own line; end at cut_after with hook. Length 5500 ±10%.
S3-1 screen: left chapters (done/generating/waiting), center TipTap manuscript, right warnings + versions. "비트 3/8 · 예상 남은 시간" + bar. Server buffers tokens, emits `sentence` at . ? ! newline. Unchecked beats dim until `beat_checked`; warnings underlined + margin mark. Always-visible pause/stop/regenerate beat. Warning: "수정 제안" regenerates beat, "무시" records reason. Edits create versions (compare/restore). Counter vs 5500. Background run; completion summary (elapsed, chars, warnings). Confirmation unit setting: beat | chapter (default) | episode.

## 11 Lock, export, backup
- Lock: stage 2 locks 1; stage 3 locks 1–2; read-only view. Incomplete cards never block advance (warning lists them + complete cards referencing them); after advance they are inactive (so are episodes whose part or main_story is inactive): shown dimmed, excluded from stage 2–3 inputs/context/checks, references to them ignored (rows kept); "all confirmed" = ≥1 active episode and all active episodes confirmed. Reopen: snapshot → delete direction_plan and all below (picks, chapters, beats, versions, states, warnings); cards kept. Warn on advance and reopen with concrete counts (e.g. "기획 단계를 다시 열면 연출 계획서와 집필한 원고 12화가 삭제돼요. 이 작업은 되돌릴 수 없어요."); red non-default button; manuscript exists → type title.
- Export (any stage): pick finished chapters (+ select all; generating disabled), show count+chars. Formats: platform copy (normalized breaks; multi-chapter "다음 화 복사"), txt, docx, hwp (write .hwpx; .hwp only via installed Hangul automation). Remember last format. Files merged (chapter titles) or one per chapter via OS dialog.
- Backup (user-initiated only): `{title}_{YYYY-MM-DD}.aiplot` zip of work data, images, app/data version; no models. Show path+size. Import from library new-book → "백업 파일에서 가져오기"; never overwrite, add "{title} (가져옴)"; newer data version → ask app update; older → migrate.

## 13 Architecture
Electron main picks port+token → starts server → server reports ready (Electron server: unpackaged `server/.venv/Scripts/python.exe -m aiplot.main --dev`, packaged `resources/aiplot-server/aiplot-server.exe` (unit 14); fresh port + 64-hex token per start, env AIPLOT_PORT/TOKEN/PARENT_PID/DATA_DIR (+ AIPLOT_DEV_ORIGIN = Vite origin in `npm run dev`; only --dev servers allow it via CORS); ready = our child printed `AIPLOT_READY {port}` after binding and /health 200; /health every 5s, unresponsive = 3 failures in a row; ready timeout 60s; crash/hang/timeout → restart ≤3 per session, then error screen with "다시 시도" (resets the budget; ignored unless in error; a launch abandoned mid-start never spawns); missing executable → error screen without restarts; quit leaves the server to stop on parent exit; renderer gets {status, baseUrl, token} via preload `window.aiplot.server` (IPC only from the app's main frame); llama.cpp not required; /health reports llama/model missing → S0-1) → server starts llama.cpp whenever binary + model become available (boot, download done, path set), health-checks, /health reports model ready. Missing files ≠ crash (no restart count). Unresponsive child: restart ≤3 then error screen. llama-server: `{data}/llama/{dir}/{executable}` from `server/config/llama.yaml`, model `{data}/models/{base gguf}`; one base profile for all roles (one model in VRAM); started in the background (API up first), ready = our child printed `listening on http://127.0.0.1:{port}` and /health 200 (a port squatter is never trusted), fresh API key per start via `LLAMA_API_KEY` (never argv) and fresh port per restart; the client asks for (url, key) per request and gets none unless that child is ready and alive, unresponsive = 3 failed /health checks in a row; restart budget per session, reset by retry ("다시 시도"); runs in a Windows Job Object with kill-on-close so a killed server never leaves it holding VRAM. /health: llama {state fake|missing_binary|missing_model|starting|ready|error|stopped, profile, restarts, message} + vram {used_mb,total_mb} from nvidia-smi (null if unavailable). Image job: unload llama model → ComfyUI → free → reload. Quit: save at beat granularity, stop children. Job queue: >10s tasks, survives screen changes, batches same role.
Router: `config/roles.yaml` role → profile, LoRA?, prompt version, sampling, thinking. `config/profiles/*.yaml`: GGUF path, chat template, thinking toggle, sampling, ctx 8192, KV type, `lora_mode hotswap|merged`; llama-server `-np 1 --cache-ram 1024` (host-RAM prompt cache keeps prefixes across roles), no `--cache-reuse`. LoRA registry: `lora/{id}.json` manifest (`schemas/lora/`) beside each adapter, with base GGUF sha256; never load mismatch. merged = per-role pre-merged GGUF + batch by role. Base swap must need config + LoRA only. `AIPLOT_FAKE_LLM=1` → fixture client (`server/tests/fixtures/llm/{role}.json`). Clients async (httpx2, llama-server `/v1/chat/completions`, thinking via `chat_template_kwargs`, JSON via `response_format` json_schema, LoRA via per-request scales); closing a stream stops generation. System message = role prompt file (comments stripped), unchanged per call; JSON output validated, 1 retry. LLM error codes: LLM_UNAVAILABLE, LLM_REQUEST_FAILED, LLM_INVALID_OUTPUT, LLM_OUTPUT_TRUNCATED (finish_reason length; JSON never accepted then), PROMPT_MISSING, ROLE_NOT_CONFIGURED, LORA_UNAVAILABLE, LORA_NOT_LOADED.
Roles (thinking, model):
- chat: turns, notes, @cards → streamed short text, first char ≤2s (off, base)
- source: last turn as `<대화>` (lines `사용자:`/`AI:`, never a word that can appear in a story such as 조수), [n]-numbered notes → JSON edits[{index, text or null = delete}] + added[] sentences, questions ≤3, similar-name pairs (card_id or null; unknown ids and self-pairs dropped); server drops out-of-range/repeated indexes, applies edits (`services/notes.py`; a replacement or added sentence missing its final mark gets a period, and goes on its own line if it would merge with a neighbour), changed = sentences not in the old notes; emptied notes or a changed sentence not ending in 다 → one more generation, then kept (emptied twice → notes unchanged + LLM_INVALID_OUTPUT) (on, base)

Server then drops out-of-range indexes, unknown paths and unknown card ids; assigns ms_/fs_ ids (keeps ids of items whose text is unchanged); sets placement (episode part_id/order/links.prev,next/worldline_id, part order) from context; restores pinned (on, base)

- direct: episode, cards (incl. the episode's world cards), chosen techniques → JSON plan (on, base + direction LoRA; baseline base)

- summary: beat/chapter/episode text → text (off, base)
